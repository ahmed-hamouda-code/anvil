How it works

Your first day, from an empty folder to a checked deploy

Six steps, all inside the window.

Workspace

Make a workspace on your PC, then add a Folder for each functional area. It holds your work and your team's naming and checklist rules.

Instances

Add your instances once and test the connection. The password is kept in Windows Credential Manager.

Item

Create an Item for each deliverable (a report, a package, an interface) and list its objects in the item editor.

Extract

Bring the real objects in from the instance into the Item, straight from your PC or from the apps server.

Validate & Drift

Check the Item against your team's rules, and see whether an instance still matches what you have.

Deploy & verify

Generate the deploy script, run it on the apps server, then register its log and let Anvil check the result.

Features

Everything between the instance and the deploy

Extract from an instance

Bring an Item's database objects in from an instance, and its application objects (concurrent programs, value sets, BI Publisher templates, workflow, OAF) as a script you run on the server or by letting Anvil run it for you over SSH.

Look up application objects

Find an application object in the database and fill in the application, language and territory its loader needs.

Validate against your rules

Check naming, prefixes and ownership for every Item before anything is deployed.

Generate governed deploy scripts

One script per target instance, with checksum, instance, backup and order checks built in, plus a matching restore script.

Detect drift

See whether an instance still matches the Item, with a side-by-side view of every difference. Compare two instances and get HTML or Excel reports (Pro).

Refresh from an instance

See exactly what would change, then update the Item's files from the instance (Pro).

Inspect the instance

Invalid objects and their compilation errors, what an object uses and what uses it, and whether an online patching cycle is open.

Team rules before deploy

A pre-deploy checklist for the content of your files: no hard-coded passwords, a ticket number in the header, and your own rules (Pro).

Workspace Settings

Folders and prefixes, the naming rule, the checklist and the deploy options in one place, shared by the whole team.

Release packages

Bundle several Items into one release that runs their deploy scripts in your order, with a suggested order and a change summary (Pro).

Create items in bulk

Turn custom programs, reports, value sets and lookups from an instance into Items, bring a schema's tables, views and packages into one Item, or pull in the custom objects a report uses (Pro).

Search, Git and reports

Search the whole workspace, commit it with local Git, and write a summary report of your work.

What's new

What's new in 1.1

  • Workspace Settings. One window for everything your team shares: Folders, naming, the checklist and, new in this version, the deploy options.
  • Splash screen. Anvil now opens with a splash screen showing the version and edition. You can turn it off in Settings.
  • Anvil themes. Two new looks in Anvil's own greens, one dark and one light. The light one is now the default.
  • Objects used by reports (Pro). For a report Item, Anvil reads its queries and data templates, finds the custom objects they use on the instance and lists them so you can add them to the Item.
  • Clearer messages. Message banners and field marks in every task window show what needs your attention.

Requirements

  • Windows 10 or 11, 64-bit.
  • Network access from your PC to the database.
  • For a database that enforces Native Network Encryption: Oracle Instant Client, 64-bit.
  • Optional: Git on your PC, for commits and the Git label.
  • Optional: an SSH login to the apps server, to run Extract on the server.

First run

The program is not code-signed yet, so Windows SmartScreen may show "Windows protected your PC". Click More info, then Run anyway. Checksums are in the zip and in the release notes, so you can check the download first.
