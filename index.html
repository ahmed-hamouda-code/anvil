1

Ground rules

Anvil prepares and checks. A person stays in charge of every change.

  • Reads, never writesAnvil only reads your database: it looks objects up and never changes them. The script you run makes the changes.
  • Never runs a deployIt writes the deploy script; a person reads it and runs it on the apps server.
  • One thing on the serverThe only script it runs on the apps server is the read-only extract, when you ask, after checking the server's key.
  • No passwords in filesPasswords stay in Windows Credential Manager. Generated scripts ask for the APPS password without showing it.
  • Nothing sent outNothing is sent to us or anyone else. The only outside call is the update check, and only when you ask.
2

How it works

Each deliverable is an Item: a folder with a short manifest that lists its objects. Anvil checks the manifest against your rules and writes the deploy script from it.

item.yamlwhat you describe
item: XXHR_PAYSLIP_REPORT
folder: HCM
type: report
description: "Custom payslip report"

objects:
  - type: package_spec
    name: XXHR_PAYSLIP_PKG
    schema: APPS
    file: db/packages/xxhr_payslip_pkg.pks
  - type: package_body
    name: XXHR_PAYSLIP_PKG
    schema: APPS
    file: db/packages/xxhr_payslip_pkg.pkb
  - type: table
    name: XXHR_PAYSLIP_STG
    schema: XXHR
    file: db/tables/xxhr_payslip_stg.sql
  # 3 more: two views and a function

You write it, or the item editor writes it for you.

Shortened, demo data. A script made for UAT stops on any other database before it changes anything, and a restore script is written beside it.

  1. Workspace once

    Make a workspace, then add a Folder for each functional area. It holds your work and your team's naming and checklist rules.

  2. Instances once

    Add your instances and test the connection. The password is kept in Windows Credential Manager.

  3. Item per deliverable

    Create an Item for each deliverable (a report, a package, an interface) and list its objects.

  4. Extract read-only

    Bring the real objects in from the instance, straight from your PC or from the apps server.

  5. Validate and Drift read-only

    Check the Item against your team's rules, and see whether an instance still matches what you have.

  6. Deploy and verify you run it

    Generate the deploy script, run it on the apps server, then register its log and let Anvil check the result.

Requirements

  • Windows 10 or 11, 64-bit.
  • Network access from your PC to the database.
  • For a database that enforces Native Network Encryption: Oracle Instant Client, 64-bit.
  • Optional: Git on your PC, for commits and the Git label.
  • Optional: an SSH login to the apps server, to run Extract on the server.
